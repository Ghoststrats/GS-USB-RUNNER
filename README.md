# 1. What Is GS USB Runner?

GS USB Runner is a free, portable Windows application developed by GhostStrats LLC to make automation and cybersecurity education easier for everyone.

The original idea behind GS USB Runner was simple:

**What if you could use an ordinary USB flash drive to carry a complete keyboard and mouse automation environment without purchasing specialized HID hardware?**

That idea became GS USB Runner.

Instead of turning a flash drive into a physical keyboard, GS USB Runner uses software to simulate keyboard and mouse input directly through Windows.

The application is powered by the Go programming language and uses a beginner-friendly scripting language called **GS Script**.

GS Script was created to make automation easier to understand.

Users can write scripts using simple, readable commands rather than learning a complicated programming language.

For example:

    PRESS WINDOWS + R
    WAIT 1 SECOND
    TYPE "notepad"
    PRESS ENTER
    WAIT 2 SECONDS
    TYPE "Hello from GS USB Runner V2.0!"
    PRESS ENTER

This script opens Windows Notepad and automatically types a message.

No expensive hardware is required.

### But GS USB Runner Has Evolved

With V2.0, GS USB Runner is no longer limited to traditional keyboard and mouse automation demonstrations.

It now includes a new system for launching custom Windows applications directly from the Runner interface.

This introduces two main execution workflows:

**1. GS Script Automation**

Traditional keyboard and mouse automation powered by the original GS Script engine.

**2. Custom GS Runners**

Standalone Windows applications launched through the new V2.0 application launcher.

This means GS USB Runner can now provide graphical educational demonstrations, network utilities, and cybersecurity awareness applications alongside its original scripting features.

**The goal is to make GS USB Runner a growing platform for free automation and cybersecurity education.**

# 4. NEW — Understanding the V2.0 Execution Architecture

One of the biggest technical improvements in V2.0 is the introduction of an additional application-launching layer.

Previously, the program primarily worked by interpreting GS Script commands.

Now the main application can also launch predefined, bundled Windows executable programs.

### Two Different Execution Systems

**System 1: GS Script Automation**

This system interprets readable instructions and simulates keyboard and mouse input.

**System 2: Custom Runner Application Launching**

This system starts standalone Windows applications packaged with GS USB Runner.

The two systems are different but are accessible through the same interface.

## Engine 1 — Original GS Script Engine

The original Go-based engine handles:

- Script interpretation.
- Keyboard simulation.
- Mouse simulation.
- Keyboard shortcuts.
- Timing and delays.
- Script validation.
- Saved-script operations.
- Existing automation functionality.
- Quick Launch building.

For example:

    TYPE "Hello World"
    PRESS ENTER
    WAIT 2 SECONDS

The engine reads each instruction and performs the corresponding supported action.

It does not require the script to be compiled into an executable before use.

## Engine 2 — New V2.0 Application Launcher

V2.0 adds a Go-based integration layer responsible for launching the bundled custom applications.

Rather than interpreting GS Script instructions, this layer requests that Windows start a specific executable.

It is responsible for functions such as:

- Preparing bundled applications.
- Launching supported custom runners.
- Tracking application processes.
- Coordinating local services.
- Handling launch requests.
- Attempting to bring application windows forward.
- Managing application shutdown.
- Connecting the original script engine with the updated interface.

### Why Is This Important?

Traditional GS Script automation is designed for keyboard and mouse input.

But not every educational application can be created using simple typing and mouse commands.

Some applications need their own graphical interfaces, networking capabilities, visual effects, and independent program logic.

The new launcher makes it possible to deliver these programs from within the GS USB Runner workspace.

### Important Distinction

The custom application launcher does not extend the GS Script language to execute arbitrary programs.

The current V2.0 release provides a predefined collection of bundled applications.

Users select those applications manually.

**GS USB Runner does not automatically execute arbitrary EXE files from a USB drive.**
